# Artifacts

Artifacts is a private shelf for material you want to keep without choosing folders or tags. Paste text or screenshots, drop a group of files, or use Upload. Text can be edited; originals are preserved for uploaded files. Title, filename and extracted content participate in full-text and typo-tolerant search, including global search with `type:artifact`.

Images in PNG, JPEG, WebP and valid static GIF formats are recognized by their bytes and read with bundled local English OCR. Text-based PDF, modern Office/OpenDocument files, common text/code formats, HTML/SVG/RTF text and ZIP filenames have bounded extraction. HTML/SVG and other active files download as opaque attachments and never execute in the viewer. Scanned PDFs, audio transcription, HEIC conversion and legacy binary Office extraction are not implemented. Unsupported files remain preserved and discoverable by their filenames.

Audio/video use the shared styled player when their format is recognized. Actual codec availability belongs to the browser: a saved file can remain downloadable even when its codec cannot play. Upload previews use browser-generated thumbnails where available, with a file card fallback.

SQLite and the configured file adapter preserve metadata/content, originals and thumbnails in the installation's saved encryption mode. Full-instance backups include the shelf. Note bundles retain their existing scope of notes and note attachments. Background recognition resumes pending items after restart. Choose Read again beside extracted text to retry an existing result, or Try again after a failure, without re-uploading. Completion updates arrive through the shared authenticated SSE stream.

The viewer keeps its title and close control above a scrolling body and a single action row below it. Long pasted text scrolls inside its field; renaming preserves unsaved text. Mobile actions use equal columns and touch-sized controls, including a labeled Tags action. OCR output preserves spacing and uses a bounded, keyboard-focusable text region.

Local OCR honors EXIF orientation and, for low-confidence images, tries complete quarter-turn images within one recognition deadline, keeping the strongest result. Recognition copies fit inside a 2400px square without cropping or enlarging smaller images; rotation swaps dimensions without clipping the document. Very low-confidence nonempty output becomes a retryable failure rather than saved gibberish. Original image bytes remain unchanged. Recognition can still misread small, blurred, skewed, or non-English text; orientation handling does not guarantee accuracy.

Limits: normal configured upload ceiling; 200,000 extracted/pasted characters; image OCR up to 60 million pixels with a 90-second recognition deadline; PDF embedded text up to 40 MiB and 400 pages; bounded Office/ODF decompression and ZIP listing. The durable scheduler runs at most two processing jobs, favoring different ready job kinds so metadata fetching is not starved by an OCR batch. Upload and extraction still read files into memory; streaming media delivery remains a separate capability.

Deleting an artifact moves it to the shared Trash and retains its encrypted original, thumbnail and extracted text. It disappears from the shelf, search and normal file endpoints. Restore returns it to Artifacts; pending extraction resumes through durable jobs. Only confirmed permanent deletion from Trash removes its stored files. Existing files that were permanently deleted before this behavior cannot be recovered by the migration.

Gallery searches request `context=0`, which searches the same full-text index without generating unused matched excerpts. Detailed search context remains available to the unified search and the default artifact search API. Gallery cards show filenames and visual previews or type icons. Files without a filename fall back to their saved title. Extracted text remains indexed and searchable, including when it is absent from the card; open an item for its text, metadata, processing status and actions. Every card uses the same 4:3 preview frame and filename footer. Images retain their proportions inside that frame without cropping; text and files use a centered type icon.

Use the Grid/List switch beside the filters to choose a layout. Grid is the desktop default; phones use the compact list. An explicit choice is saved in the browser and retained through search, filters and reloads. The list shows a small thumbnail or type icon, filename and action menu. Loading placeholders match the selected layout.
